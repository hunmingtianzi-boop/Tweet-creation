# 组织型公众号工作流使用说明

这套工作流用于“换一个组织或公众号，仍能继续生成属于它的文章、视觉素材和微信交付文件”。

当前可执行发布版只支持 Codex Desktop。第一次拉取或换机器时，必须先读[克隆、安装与登录前置条件](host-prerequisites.md)，安装同一 release 的三个仓库 Skill，另行安装并把 `codex-with-chatgpt` 绑定到当前精确 workspace，准备内置 Browser 的 ChatGPT 登录、Ardot Remote 登录与目标 file/root 权限；`delivery/full` 再准备目标微信公众号。其他 LLM/harness 只能阅读迁移契约，不能直接运行或声称兼容。

## 使用归属

使用本仓库工作流制作的公开推文，在所有正文和自定义 footer 之后必须保留一次可见文本：`感谢拓浙 AI 生态提供本篇内容生产工作流支持。`。它是仓库级使用归属，不是组织品牌文案；Ardot 中保留末位原生可编辑文本，编译、handoff v5 和草稿回读均会校验。

## 零、启动环境自检

任何组织材料读取、Ardot 创建或公众号操作之前，先从源码 clone 运行 `release_skills.py clone-check --phase <phase>`，再按[运行环境启动自检](runtime-preflight.md)执行平台与 live-session 审计。当前 Codex Desktop 由已验证安装 release + adapter allowlist + 本会话实际 model-visible registry id 生成非签名 census intent，再由 census + 紧凑 target 文件生成 profile。不要手写 Skill `loaded/available`、provider/session、host export 或本地 processor 状态。profile 必须绑定当前 worktree、adapter、installed release、registry census、实际 callable 和无凭据 Ardot/微信链接。把当前模型注册表中每个实际可见 ID 作为 `clone-check --visible-tool-id ID` 重复参数传入。返回 `current_task_reload_required: true` 时先重载/新开 Codex 任务，不读材料、不打开 Ardot 也不继续写公众号。

先从已加载的顶层 `org-wechat-studio/SKILL.md` 解析绝对
`ORG_WECHAT_RUNTIME_ROOT`，再将用户项目中 Git-ignored、create-once 的绝对
目录定义为 `ORG_WECHAT_SESSION_ROOT`。保持用户项目为 cwd，不 `cd` 到
安装包，不在 Skill 下写 `output/`。macOS 临时路径必须使用解析后的
`/private/tmp/...`，不使用 `/tmp/...`。

除下面 create-once release manifest 安装自检外，本文所有公开工作流 CLI
都必须使用绝对 `ORG_WECHAT_RUNTIME_ROOT` 下的 `secure_runner.py` 和绝对
target；组织包的 `list/search` 也不例外。

```bash
ORG_WECHAT_RUNTIME_ROOT=/ABSOLUTE/SKILLS_ROOT/org-wechat-studio
ORG_WECHAT_SESSION_ROOT=/ABSOLUTE/USER/PROJECT/output/runtime/SESSION_UNIQUE

python3 -I -S "$ORG_WECHAT_RUNTIME_ROOT/scripts/release_skills.py" verify-installed \
  /ABSOLUTE/SKILLS_ROOT/.org-wechat-release-manifests/RELEASE_SHA.json \
  --skills-root /ABSOLUTE/SKILLS_ROOT

python3 -I -S "$ORG_WECHAT_RUNTIME_ROOT/scripts/secure_runner.py" --platform-audit

python3 -I -S "$ORG_WECHAT_RUNTIME_ROOT/scripts/secure_runner.py" \
  "$ORG_WECHAT_RUNTIME_ROOT/scripts/runtime_preflight.py" \
  init-current-session-census \
  --phase migration --session-id CURRENT_HOST_SESSION_ID \
  --visible-tool-id image_gen__imagegen \
  --visible-tool-id view_image \
  --visible-tool-id codex-with-chatgpt \
  --visible-tool-id browser:control-in-app-browser \
  --visible-tool-id mcp__node_repl__js \
  --skills-root /ABSOLUTE/INSTALLED/SKILLS/ROOT \
  --release-manifest /ABSOLUTE/INSTALLED/SKILLS/ROOT/.org-wechat-release-manifests/RELEASE_SHA.json \
  --workspace-root "$ORG_WECHAT_RUNTIME_ROOT" \
  --output "$ORG_WECHAT_SESSION_ROOT/registry-census-UNIQUE.json"

python3 -I -S "$ORG_WECHAT_RUNTIME_ROOT/scripts/secure_runner.py" \
  "$ORG_WECHAT_RUNTIME_ROOT/scripts/runtime_preflight.py" init-profile \
  "$ORG_WECHAT_SESSION_ROOT/registry-census-UNIQUE.json" \
  "$ORG_WECHAT_SESSION_ROOT/target.json" \
  --workspace-root "$ORG_WECHAT_RUNTIME_ROOT" \
  --phase migration \
  --output "$ORG_WECHAT_SESSION_ROOT/migration-profile-UNIQUE.json"
```

启动默认要求：

- 每次换 clone、机器、Codex 会话、adapter/provider route 或 trusted bundle 时，先跑 `--phase migration --binding-only`。该阶段只绑定两类生图与验图，并在读材料前强制完成一次 `neutral-rgba-route-probe-v1`；如果目标是其他 LLM/harness，当前 release 直接停止，不能用 migration 命令把未审核宿主“自测成支持”；
- `authoring/full` 同时绑定 `image.generate.opaque`、RGBA 生产路由与 `image.inspect`。Codex Desktop 默认的 RGBA 路由是 `chatgpt-web-image-route` + `codex-with-chatgpt` + 内置 Browser，再经 `scripts/prepare_micro_cutout.py`；本地 `image_gen__imagegen` 只可承担不透明源图，不得冒充 Alpha 生产器；
- `ardot.read` + `ardot.write` + `ardot.export`，或通过实际登录探测的 UI 路线；
- `wechat.draft`，或能读取当前目标账号的 Browser/Computer Use 路线；草稿 API 不推导 `wechat.current-session-authority`，当 `terminal_state=publish` 且 `mode=api` 时还必须有独立发布权限或 portable receipt，否则只能保持草稿终态或选已声明 UI live route；
- `host.migration.finalize`、`filesystem.access.lease`、`host.receipt.attest` 与 provider policy hook 是可选的保证/政策升级，缺少它们不是登录错误，也不单独阻断 `authoring/full`。正式微组件必须通过完整当前会话 migration/request/create-once ingestion/raw/RGBA 链，并标记 operator/harness-trusted、`host_attested=false`、`portable=false`。普通 Python callback 只能 veto，不能升级保证；
- `secret.resolve` 只在当前 `artifact_inventory` 存在 eligible watermark carriers 时要求；无载体的完整清单不因缺水印 secret 阻断；
- Python、Pillow、cryptography（Ed25519 验签）、全部本地引用与项目 Skill SHA 一致。安装后 runtime 可为只读；迁移写入与可写探针只落在已验证的 Git-external/Git-ignored `--session-root`。

Ardot 启动报告分别显示 `configured`、`model_visible`、
`live_authenticated/target_access_verified` 和 `last_mutation_outcome`；任何一层不得
由前一层推导。微信 API 也先用 `wechat_publisher.py preflight-account` 只读验证
`draft/count` + `material/get_materialcount`，再单独验证上传、草稿写入、浏览器回读和发布。

不要把 token、Cookie、AppSecret、密钥、ChatGPT 对话 URL/配对码或当前微信带 token 的编辑 URL写入 profile。`migration/authoring/full` 在读材料前执行 host setup actions：C2C update/sandbox、精确 worktree session、tunnel choice、setup、project/connector/workspace identity、workspace-info 和 doctor 必须分别闭合，不得都归类为“登录”。Browser 生成并下载 original 后，立即将宿主返回的绝对路径交给 `scripts/ingest_browser_download.py`，拒绝 symlink/覆盖并对源/目标 SHA+bytes 做 create-once 绑定；该报告不冒充已签名 Browser 事件。随后才运行 native-alpha-first RGBA 与三底验收。当前会话终态为 `operational_ready: true` 且 `phase_ready: false`；只有真实 `host.migration.finalize` 签名 receipt 能产生可携带的 `phase_ready: true`。两者都不允许手改报告或模型自报。

新组织没有 Ardot file/root 时不要伪造链接：迁移自测通过后，再用 `--phase bootstrap --binding-only` 检查 `ardot.create`，宿主轨迹确认 create-design/page callable 后只创建空白设计，随即用新 file/root 重跑目标阶段（默认 `full`，明确只做 Ardot 时为 `authoring`）。`bootstrap` 不要求生图、ChatGPT、验图、水印 secret、微信账号或登录。

## 二、迁移到新公众号

不读取任何组织材料，先使用上一节与当前宿主匹配的 census 命令和 `init-profile --phase migration` 生成最小 profile。它不含 Ardot/微信链接，只绑定 opaque、RGBA、inspect；RGBA 项由 adapter 生成 `migration_probe_contract: neutral-rgba-route-probe-v1` 和真实 `generation_route_id`，不由操作者手填。然后运行：

```bash
python3 -I -S "$ORG_WECHAT_RUNTIME_ROOT/scripts/secure_runner.py" \
  "$ORG_WECHAT_RUNTIME_ROOT/scripts/runtime_preflight.py" \
  "$ORG_WECHAT_SESSION_ROOT/migration-profile-UNIQUE.json" \
  --workspace-root "$ORG_WECHAT_RUNTIME_ROOT" \
  --session-root "$ORG_WECHAT_SESSION_ROOT" \
  --phase migration --binding-only \
  --output "$ORG_WECHAT_SESSION_ROOT/migration-binding-UNIQUE.json"
```

立即执行报告的 `host_setup_actions`，以 Browser 返回的绝对下载路径完成 create-once ingestion，再直接执行 case 内含绝对 installed runtime 和 `{binding_report}` 占位的 `prepare_migration_probe.py` 命令。它只生成不可注册的 migration-only lineage；attempt 2 还必须引用 attempt 1 的 create-once 失败证据。完成 native-alpha-first processor 和透明/浅/深三底验收后，当前 Codex Desktop 再运行报告提示的 `finalize-current-session-migration`，得到 `operational_ready: true`的同会话续跑文件。宿主轨迹未闭合前，下面的 `orgs.py init` 不得运行。ChatGPT-web 路线保持同一 C2C-managed conversation，不新开临时验证 chat；中性 probe 仅为非语义灰度校准，不是组织资产，不得作为视觉参考或正式资产证据。

进入 `bootstrap/authoring/delivery/full` 时，当前会话路径要用新阶段和当时实际可见 registry id 重跑 `init-current-session-census`，再从新 census 生成 profile；阶段绑定的 migration census 不可直接复用。这不重复生成中性 smoke image；`authoring/full` 继续引用已消费的同会话迁移结果或 portable receipt。

首先为该公众号建立独立组织包：

```bash
python3 -I -S "$ORG_WECHAT_RUNTIME_ROOT/scripts/secure_runner.py" \
  "$ORG_WECHAT_RUNTIME_ROOT/scripts/orgs.py" init new-account-id \
  --name "新组织或公众号名称" \
  --root organizations
```

将生成：

```text
organizations/new-account-id/
├── organization.json
├── sources.json
├── components.json
├── assets.json
├── ardot.json
└── assets/
    ├── official/
    ├── photos/
    ├── generated/
    └── derived/
```

然后完成组织调研：

1. 收集本轮明确允许的官网说明、原始文案、Logo、活动照片与品牌规范。默认不要打开旧推文布局、旧截图/PDF、旧 Ardot 或其他组织 pack；获准的历史文字只能用于 voice/fact，不能用于视觉校准。只有用户明确要求学习某个风格时，才进入 [style-options.md](style-options.md) 的 `explicit-style-grammar` 分支。
2. 在 `sources.json` 中记录来源和可核验事实。
3. 在 `organization.json` 中确认受众、内容支柱、语气、视觉色彩、视觉母题和文章类型。
4. 默认在 `organization.provenance` 填写 `visual_reference_policy: source-zero`、本轮 `visual_input_source_ids`、显式 `visual_input_allowed_roots`（默认 `inputs/current`）、四类旧视觉排除项和 `isolation_reviewed_at`。每个 source 同时写当前内容 SHA-256；父级 symlink、allowlist 外路径、`output/examples/other-org`或“旧稿/往期/成稿”目录一律阻断。若用户明确选了 style preset，则改用 `explicit-style-grammar` 的来源、scope、review time 与六项 non-copy 契约；后续组织把 preset JSON 登记为来源，不重新打开最初参考。
5. 为每个文章类型提出 2–3 条视觉路线，先在全新 Ardot 页面做 Hero、章节、照片编排、微型插图和信息密度小样，不直接做全文。已审核 preset 只能作为其中一个 route 级选项；未带 `style_grammar` 的 sibling routes 仍是 source-zero。Hero/章节同时对比可编辑表现型标题字，至少批准两个 construction recipe；每个 recipe 至少两种非字体手法与两个可编辑图层，只换字体不算艺术字。AI 底图必须先做一个母版与 1–3 个同系列变体，整个 family 只能选一种 `light`/`dark` surface mode，并登记 family/variant、归一化 copy-safe zone、正文颜色、最低 4.5 对比度和复制区最大 0.10 亮度标准差，不能逐章随机生成。组织包默认启用 `generated_image_watermark.mode: required`；密钥来自仓库外的 `PROVENANCE_WATERMARK_KEY`，必须是以 `hex:` 或 `base64:` 表示的至少 32 个随机字节，不能写进组织包。

```bash
python3 -I -S "$ORG_WECHAT_RUNTIME_ROOT/scripts/secure_runner.py" \
  "$ORG_WECHAT_RUNTIME_ROOT/scripts/build_visual_directions.py" \
  organizations/new-account-id recruitment \
  --output output/new-account-id/visual-directions.json
```

仓库当前内置的可选 preset 可在 `style-presets/` 查看。`prismatic-paper-editorial` / 绚烂纸本是暖纸、水彩洗染、干刷与颗粒的连续阅读面语法，不是默认配色模板。选择时只把 preset 的 `grammar` 写入被选 route，组织色、字体、照片与组件仍由本组织材料重新校准。`orgs.py validate` 会把 route SHA 与仓库 canonical preset 对照；修改 token 后重新签一个自有 SHA 也不能通过。

6. 用户批准小样后，把 route、background family、typography recipes 与 Ardot 文件/页面/节点回写到 `organization.visual.calibration`。先登记最终 master/companion PNG，再运行下面的验证；它会直接分析像素，阻断明暗跳变、大块黑白、复制区杂乱和文字对比不足。只有通过后才创建文章 root。组织事实与视觉同时确认后，才将状态改为 `confirmed`。`provisional` 组织会被阻断在全文之前。

```bash
python3 -I -S "$ORG_WECHAT_RUNTIME_ROOT/scripts/secure_runner.py" \
  "$ORG_WECHAT_RUNTIME_ROOT/scripts/orgs.py" validate organizations/new-account-id
```

如果同一组织有多个公众号：

- 语气、受众、视觉与栏目完全一致时，可共用组织包，只更换发布连接。
- 如果是子品牌、校园分会、招新号或不同受众频道，建议建立独立组织包，避免品牌混同。

## 三、为新公众号生成对应资产

先生成资产计划：

```bash
python3 -I -S "$ORG_WECHAT_RUNTIME_ROOT/scripts/secure_runner.py" \
  "$ORG_WECHAT_RUNTIME_ROOT/scripts/orgs.py" asset-plan \
  organizations/new-account-id recruitment \
  --output output/new-account-id/recruitment-asset-plan.json
```

资产计划会根据该组织的：

- 品牌色与视觉母题；
- 文章类型；
- 当前视觉路线；
- 已有素材库；
- 真实照片与生成图像的边界；

输出每个资产位的状态、建议尺寸、保存目录和生图提示蓝图。

系统可以生成：

- 封面或开场背景；
- 章节主视觉；
- 透明背景点缀插画；
- 流程、系统与技术解释图；
- 照片裁切、压缩和派生版本；
- 与组织视觉路线一致的组件背景资产。

不会生成：

- Logo 或组织标志；
- 报名码、群二维码或公众号二维码；
- 冒充真实人物、活动现场或项目成果的图片；
- 带有生成中文、虚假数据或合作伙伴标志的图像。

将用户提供或已审核的文件放入对应目录。对于不透明的 `generated-illustrative` 底图或纯生成 raster 封面，先保留母版并生成带来源水印的 final derivative；公开报告留在 pack 内，raw watermark ID 的私密记录必须留在 pack 和 Git 之外。先创建私密目录并设定 `PROVENANCE_WATERMARK_PRIVATE_ROOT`；`--private-record` 必须位于该目录下：

```bash
python3 -I -S "$ORG_WECHAT_RUNTIME_ROOT/scripts/secure_runner.py" \
  "$ORG_WECHAT_RUNTIME_ROOT/scripts/provenance_watermark.py" embed \
  organizations/new-account-id/assets/generated/recruitment-hero-raw.png \
  organizations/new-account-id/assets/derived/recruitment-hero-final.png \
  --key-epoch 1 \
  --report organizations/new-account-id/assets/derived/recruitment-hero-watermark.json \
  --private-record /secure/private-registry/recruitment-hero.json
```

1024×1536 等常见底图若超过 V1 嵌入像素上限，加 `--resized-carrier organizations/new-account-id/assets/derived/recruitment-hero-carrier.png`。工具会一次性创建等比 LANCZOS carrier，在报告绑定原图/carrier 的 SHA 和尺寸；不会独立抬高短边，极端长宽比直接失败。登记时 `--watermark-source` 指向 carrier，再用 `--watermark-original-source` 指向 1024×1536 原图；验收会在内存中重算 carrier 字节，不只信报告里的尺寸。

只有报告达到 `local_verified`、`PSNR >= 42 dB` 且完整画面通过 `390px-if-larger → JPEG Q75` 模拟才注册 final 文件：

```bash
python3 -I -S "$ORG_WECHAT_RUNTIME_ROOT/scripts/secure_runner.py" \
  "$ORG_WECHAT_RUNTIME_ROOT/scripts/orgs.py" register-asset organizations/new-account-id \
  --id visual.recruitment-hero \
  --kind background \
  --title "Recruitment hero background" \
  --location assets/derived/recruitment-hero-final.png \
  --watermark-source assets/generated/recruitment-hero-raw.png \
  --watermark-report assets/derived/recruitment-hero-watermark.json \
  --origin generated-illustrative \
  --style campus-editorial \
  --use recruitment \
  --visual-role illustrative-atmosphere \
  --background-family-id current-family-v1 \
  --background-variant master
```

登记时会用外部密钥重新检测当前像素、独立重跑传输模拟、回算母版/final/公开报告 SHA 与 PSNR，并拒绝源文件覆盖、伪造报告、未知字段、低于视觉门槛的结果或 pack 外路径。成品、公开报告和私密记录都不覆盖已存在路径。真实照片、用户/官方图片、Logo、二维码、透明 `article-micro`、SVG/SMIL 与 QA 截图不修改。V1 不承诺裁切、加边、旋转或透视变换后的截图检出；完整合同见 [provenance-watermark.md](provenance-watermark.md)。

日常查水印用 `detect`（密钥仍由外部 secret manager 注入）：

```bash
audit_dir="$(mktemp -d)"
python3 -I -S "$ORG_WECHAT_RUNTIME_ROOT/scripts/secure_runner.py" \
  "$ORG_WECHAT_RUNTIME_ROOT/scripts/provenance_watermark.py" detect \
  "/absolute/path/recruitment-hero-final.png" \
  --report "$audit_dir/local-detect.json"
```

## 六、投递到公众号

1. 通过目标公众号连接上传正文图片，将本地路径替换为该账号返回的微信图片 URL。SVG `<image>` 只能使用 `mmbiz.qpic.cn` URL。
2. 单独把当前封面上传到目标账号永久素材，取得该账号专属 `media_id`，并在草稿 payload 中设为 `thumb_media_id`。正文图片 URL、SVG 图片和另一账号的素材 ID 均不能代替封面。
3. 若存在动态候选，先运行固定策略校验：

   ```bash
   python3 -I -S "$ORG_WECHAT_RUNTIME_ROOT/scripts/secure_runner.py" \
     "$ORG_WECHAT_RUNTIME_ROOT/scripts/wechat_interaction_policy.py" candidate.html \
     --fallback fallback.html \
     --output interaction-policy-report.json
   ```

   只允许无 JavaScript、无 ID、元素自身 `begin="click"` 的 `<set>` / `<animateTransform>` 与 CSS 横滑；`details`、跨 ID timing 和无静态等价物直接阻断。
4. 创建或更新一个草稿，然后回读标题、摘要、正文顺序、图片 URL、实际封面、fallback 哈希和 SMIL 结构签名。结构回读成功只代表未被清洗，不代表手机端会执行动画。
5. 动态版只有在目标账号相同、策略版本相同且未过期的 iOS/Android 真机能力档案通过后才可保留；否则更新同一草稿为静态回退并再次回读，不新建重复草稿。
6. 无 API 授权时可退回浏览器导入，但必须保存后重新打开并实际看到封面与正文，不能把“粘贴完成”报告成“已验证草稿”。
7. 正式发布前再次征得明确确认。

组织包中不保存 AppSecret、access token 或其他账号密钥。

## 七、迁移后能否自动生成对应文件资产

可以，但前提是先完成一次组织建模与视觉校准。之后每篇文章都能稳定生成：

- 该公众号对应的 Ardot 原生长文画板；
- 复用或新增的组织组件实例；
- 每篇文章先生图得到的专属微型视觉套件；
- 与路线一致的封面/章节/解释图资产计划；
- `ardot-manifest.json` 装配清单；
- 视觉通过后的微信草稿投递文件。

系统不会假设“所有 AI 组织都长一样”。迁移结果由组织变量模式、路线、组件变体、真实素材和文章类型共同决定。
