# 组织型公众号工作流使用说明

这套工作流用于“换一个组织或公众号，仍能继续生成属于它的文章、视觉素材和微信交付文件”。

## 一、已有组织包时

查看可用组织：

```bash
python3 scripts/orgs.py list
```

验证组织包：

```bash
python3 scripts/orgs.py validate organizations/<organization-id>
```

查看某类文章适合的视觉路线与组件：

```bash
python3 scripts/orgs.py recommend organizations/<organization-id> recruitment
```

搜索可复用素材：

```bash
python3 scripts/orgs.py search organizations/<organization-id> "招新 校园"
```

## 二、迁移到新公众号

首先为该公众号建立独立组织包：

```bash
python3 scripts/orgs.py init new-account-id \
  --name "新组织或公众号名称" \
  --root organizations
```

将生成：

```text
organizations/new-account-id/
├── organization.json
├── sources.json
├── components.json
├── assets.json
├── ardot.json
└── assets/
    ├── official/
    ├── photos/
    ├── generated/
    └── derived/
```

然后完成组织调研：

1. 收集本轮明确允许的官网说明、原始文案、Logo、活动照片与品牌规范。不要打开旧推文布局、旧截图/PDF、旧 Ardot 或其他组织 pack；获准的历史文字只能用于 voice/fact，不能用于视觉校准。
2. 在 `sources.json` 中记录来源和可核验事实。
3. 在 `organization.json` 中确认受众、内容支柱、语气、视觉色彩、视觉母题和文章类型。
4. 在 `organization.provenance` 填写 `visual_reference_policy: source-zero`、本轮 `visual_input_source_ids`、四类旧视觉排除项和 `isolation_reviewed_at`。
5. 为每个文章类型提出 2–3 条视觉路线，先在全新 Ardot 页面做 Hero、章节、照片编排、微型插图和信息密度小样，不直接做全文。Hero/章节同时对比可编辑表现型标题字，至少批准两个 construction recipe；每个 recipe 至少两种非字体手法与两个可编辑图层，只换字体不算艺术字。AI 底图必须先做一个母版与 1–3 个同系列变体，整个 family 只能选一种 `light`/`dark` surface mode，并登记 family/variant、归一化 copy-safe zone、正文颜色、最低 4.5 对比度和复制区最大 0.10 亮度标准差，不能逐章随机生成。

```bash
python3 scripts/build_visual_directions.py \
  organizations/new-account-id recruitment \
  --output output/new-account-id/visual-directions.json
```

6. 用户批准小样后，把 route、background family、typography recipes 与 Ardot 文件/页面/节点回写到 `organization.visual.calibration`。先登记最终 master/companion PNG，再运行下面的验证；它会直接分析像素，阻断明暗跳变、大块黑白、复制区杂乱和文字对比不足。只有通过后才创建文章 root。组织事实与视觉同时确认后，才将状态改为 `confirmed`。`provisional` 组织会被阻断在全文之前。

```bash
python3 scripts/orgs.py validate organizations/new-account-id
```

如果同一组织有多个公众号：

- 语气、受众、视觉与栏目完全一致时，可共用组织包，只更换发布连接。
- 如果是子品牌、校园分会、招新号或不同受众频道，建议建立独立组织包，避免品牌混同。

## 三、为新公众号生成对应资产

先生成资产计划：

```bash
python3 scripts/orgs.py asset-plan \
  organizations/new-account-id recruitment \
  --output output/new-account-id/recruitment-asset-plan.json
```

资产计划会根据该组织的：

- 品牌色与视觉母题；
- 文章类型；
- 当前视觉路线；
- 已有素材库；
- 真实照片与生成图像的边界；

输出每个资产位的状态、建议尺寸、保存目录和生图提示蓝图。

系统可以生成：

- 封面或开场背景；
- 章节主视觉；
- 透明背景点缀插画；
- 流程、系统与技术解释图；
- 照片裁切、压缩和派生版本；
- 与组织视觉路线一致的组件背景资产。

不会生成：

- Logo 或组织标志；
- 报名码、群二维码或公众号二维码；
- 冒充真实人物、活动现场或项目成果的图片；
- 带有生成中文、虚假数据或合作伙伴标志的图像。

将用户提供或已审核的文件放入对应目录，再注册：

```bash
python3 scripts/orgs.py register-asset organizations/new-account-id \
  --id visual.recruitment-hero \
  --kind background \
  --title "Recruitment hero background" \
  --location assets/generated/recruitment-hero.png \
  --origin generated-illustrative \
  --style campus-editorial \
  --use recruitment \
  --visual-role illustrative-atmosphere \
  --background-family-id current-family-v1 \
  --background-variant master
```

companion 使用相同 family ID，并改为 `--background-variant companion`；在 `organization.visual.calibration.background_family` 同时登记 master、1–3 个 companion，以及：

```json
{
  "surface_mode": "dark",
  "copy_safe_zone": {"x": 0.12, "y": 0.16, "width": 0.76, "height": 0.58},
  "body_text_color": "#FFFFFF",
  "minimum_contrast_ratio": 4.5,
  "maximum_copy_safe_stddev": 0.10
}
```

登记完全部底图后必须再次运行 `python3 scripts/orgs.py validate organizations/new-account-id`。不允许用一张浅色、一张深色拼成 family，也不能在验证失败时进入全文排版。

Logo 或二维码的注册示例：

```bash
python3 scripts/orgs.py register-asset organizations/new-account-id \
  --id brand.logo \
  --kind logo \
  --title "Canonical logo" \
  --location assets/official/logo.png \
  --origin official \
  --style canonical \
  --use all
```

## 四、在 Ardot 生成可编辑文章

根据 `references/article-schema.md` 创建 `article.json`。先写 4–10 个叙事章节，确定每章命题、构图、视觉意图与 block 覆盖：

```bash
python3 scripts/build_storyboard.py article.json \
  --output output/new-account-id/article-slug/storyboard-plan.json
```

只有 `ready_for_visual_kit: true` 才生成文章专属小组件/小插图计划：

```bash
python3 scripts/build_visual_kit.py article.json \
  --org organizations/new-account-id \
  --output output/new-account-id/article-slug/visual-kit-plan.json
```

先按计划生成四枚不同的微型视觉资产。每枚图必须写明 `storyboard_chapter`、正文原句 `source_text`、`concrete_subject`、`action`、`composition_role` 和 `placement`。不再把整篇正文粗暴塞进四个通用生图提示词。

逐张运行真实 Alpha、尺寸与角色宽高比检查：

```bash
python3 scripts/inspect_asset.py path/to/micro.png --role floating-spot
```

先把登记 ID 写入 `article.visual_kit.assets`；此时若尚未有 Ardot component node，计划仍会保持 `ready_for_layout: false`。资产注册示例：

```bash
python3 scripts/orgs.py register-asset organizations/new-account-id \
  --id spot.article-object \
  --kind illustration \
  --title "Article object spot" \
  --location assets/generated/article-object.png \
  --origin generated-illustrative \
  --style article-specific \
  --use recruitment \
  --role floating-spot \
  --generated-for ARTICLE_ID \
  --visual-role article-micro
```

四类角色不能共用图片；四枚图都必须在资产登记中明确绑定当前 `article_id`。旧的通用装饰图不能解锁排版。验图后先在 Ardot 建四个原生 Ornament 组件，再把每个组件的 `file_url`、`node_id`、exact `name` 写回 `article.visual_kit.assets`。此后才把 status 设为 `approved` 并重跑计划。

然后为本篇文章选定 2–4 个 Hero/章节/观点/关键短语/CTA 表现型字体时刻。每个时刻必须引用正文原句和批准的 `recipe_id`，至少实现两种非字体构造手法，并在 `construction` 中写回独立的 Ardot 文本/矢量 node IDs；主文本的 `file_url/node_id/style_id/name` 也必须完整。只换字体会直接失败。完整字段见 `references/expressive-typography.md`。

```bash
python3 scripts/build_ardot_manifest.py article.json \
  --org organizations/new-account-id \
  --output output/new-account-id/article-slug/ardot-manifest.json
```

清单会包含：

- 目标 Ardot 文件、页面、变量集和组织模式；
- 本篇采用的视觉路线与组件变体；
- 每个区块的真实 Ardot 组件名和覆盖内容；
- 需要上传的组织资产及本地路径；
- 视觉 QA 阻断项与微信投递边界。
- 每个区块的开放式构图模式、微型视觉角色与方框比例限制。

如果 `ardot.json` 仍是 `not-linked`，先在 Ardot 中建立或选择组件系统，再填写：

- `design_file.url` 与 `file_id`；
- `variable_mode`；
- `page_names`；
- `component_aliases`。

随后按清单在 Ardot 中：

1. 先把四类小插图做成无默认底色/描边/圆角的原生 Ornament 组件，并确认表现型字体仍是可编辑文本节点。
2. 应用该组织的变量模式。
3. 获取或创建 Hero、章节、观点、步骤/流程、案例和 CTA 组件变体。
4. 建立 390 px 文章根 Frame；所有区块默认开放、无外框。
5. 用插图切入文字边缘、章节转场、连续路径和 CTA 落点，不能用方框替代视觉节奏。
6. 按叙事章节装配，不按“一个 block = 一个带外框组件”机械堆叠。
7. 从同一 article root 分别导出 Hero、章节、证据、复杂区块和 CTA 五个不同 Ardot 节点的本地 390 px PNG，记录 node、chapter、SHA-256、实际宽高与 capture 时间到 v2 `visual-review.json`。
8. 逐项检查主体相关性、风格一致、装饰裁切、尺度变化、照片/插图和谐、泛 AI 装饰、无意义标签、编辑节奏、手机可读性、开放构图、信息密度、底图家族一致性、表现型字体与无烘焙字图。
9. 为五个截图节点记录与截图哈希绑定的密度样本。默认 `compact-editorial`：正文 15–17 px、行高 1.45–1.62、中文字距 -0.2–0 px、段距 8–14 px、章内主间隔 24–40 px、普通正文区内容占用率 68%–90%、最大无意空洞不超过 20%。
10. 视觉确认后将 Ardot 保留为唯一可编辑源。

详细规则见 `references/ardot-workflow.md`。

## 五、生成微信投递文件

先验证独立截图验收文件：

```bash
python3 scripts/build_visual_review.py visual-review.json --article article.json
```

把路径写入 `article.visual_review_file`。只有验收通过后，才运行隐藏的最终适配器：

```bash
python3 scripts/compile_wechat.py article.json \
  --org organizations/new-account-id \
  --output output/new-account-id/article-slug \
  --check
```

输出目录包含：

- `visual-kit-plan.json`：文章专属小组件/小插图生产与验收清单。
- `storyboard-plan.json`：叙事章节、构图和 block 覆盖校验。
- `ardot-manifest.json`：Ardot 开放式构图装配与 QA 清单。
- `visual-review.json`：实际 Ardot 节点的 v2 截图、哈希、尺寸、capture 与密度检查证据。
- `index.html`：内部传输调试预览，不是设计源。
- `wechat.html`：微信内联样式传输片段，不是设计源。
- `compile-report.json`：组织、路线、组件、来源、素材与错误报告。
- `assets/`：本篇文章实际使用的本地图片副本。

`--check` 会阻断 source-zero 隔离未确认、未校准/仍为 provisional、底图 family 不完整、缺少分镜、四枚微组件不独立/无 Alpha/无 Ardot node 证据、缺少或烘焙的表现型字体、不完整或哈希不符的五类 Ardot 截图，以及任一视觉检查失败的文章。

## 六、投递到公众号

1. 通过目标公众号连接上传正文图片。
2. 将 `wechat.html` 中的本地路径替换为微信图片 URL。
3. 单独上传封面素材。
4. 创建草稿并回读检查。
5. 正式发布前再次征得明确确认。

组织包中不保存 AppSecret、access token 或其他账号密钥。

## 七、迁移后能否自动生成对应文件资产

可以，但前提是先完成一次组织建模与视觉校准。之后每篇文章都能稳定生成：

- 该公众号对应的 Ardot 原生长文画板；
- 复用或新增的组织组件实例；
- 每篇文章先生图得到的专属微型视觉套件；
- 与路线一致的封面/章节/解释图资产计划；
- `ardot-manifest.json` 装配清单；
- 视觉通过后的微信草稿投递文件。

系统不会假设“所有 AI 组织都长一样”。迁移结果由组织变量模式、路线、组件变体、真实素材和文章类型共同决定。
